# Scope v1 — зафиксировано 2026-10-01

> **Статус: в работе.**

V1 — первый рабочий релиз платформы. Разработчик входит через GitHub, заполняет профиль с контактами, создаёт проекты с демо, скриншотами и привязанным репозиторием, публикует их; посетитель открывает страницу проекта, демо, данные GitHub и связывается с разработчиком. Всё работает в продакшне по HTTPS, с бэкапами и мониторингом.

## Что входит

1. **Аутентификация** — вход и выход через GitHub OAuth.
2. **Профиль** — редактирование, публикация, публичная страница.
3. **Контакты** — email, Telegram, LinkedIn, телефон и «другие способы связи».
4. **Проекты** — CRUD, публикация, архивация, видимость.
5. **Витрина** — до 3 избранных проектов с порядком.
6. **Страница проекта** — `/u/{slug}/projects/{id}` с демо, скриншотами и блоком GitHub.
7. **Интеграция с GitHub** — список репозиториев, привязка, импорт, синхронизация.
8. **Инфраструктура** — Docker, CI, Nginx, HTTPS, бэкапы, мониторинг.

Не входит в V1: аналитика (V1.1), рабочее пространство с кодом, опыт/навыки/образование, поиск кандидатов, вакансии, сообщения.

- **8.1, 8.2, 8.5** не названы блокерами запуска — нужно ли ждать их. - **README репозитория** — показывать ли до запуска V1 (требует отдельного решения о рендеринге, [0018](../adr/0018-github-sync-v1.md)). Решено 2026-11-20 (владелец): вне V1.
- **Object storage в 9.3** — Решено 2026-11-17 (владелец): завершается с фазой 4. Хранилище — том на диске хоста, не S3 ([0022](../adr/0022-media-on-host-volume.md)).
- **Цели, архитектура, хайлайты** проекта ([0015](../adr/0015-project-entities.md)) — входят ли в V1. Решено 2026-11-20 (владелец): вне V1.
- **Срок хранения сессий** (к 9.7) — просроченные строки `auth_sessions` не удаляются никогда. Решено 2026-11-20: при каждом входе удаляются просроченные сессии всех пользователей ([0028](../adr/0028-account-deletion-hard-and-immediate.md)).

- **Юридическая часть запуска** (к 9.8b) — юриста нет. Варианты: разовая платная проверка `/privacy` и вопросов [0020](../adr/0020-contacts-separate-table.md), «Видимость и персональные данные»; или строгий вариант без юриста — сервер и бэкапы в РФ, уведомление в Роскомнадзор, оператор на `/privacy` и отдельный шаг до запуска: согласие на распространение при публикации профиля (отметка с датой, миграция, чекбокс, текст согласия). Решает владелец перед продакшном.
