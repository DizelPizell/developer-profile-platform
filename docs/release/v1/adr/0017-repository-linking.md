# ADR-0017: Репозиторий — общий ресурс; привязка хранит связь разработчика с ним

- **Статус:** принято 2026-10-22
- **Релиз:** v1
- **Связано:** [0015](0015-project-entities.md), [0016](0016-github-public-only.md), [0018](0018-github-sync-v1.md)

## Контекст

Несколько разработчиков могут ссылаться на один GitHub-репозиторий. Нужно решить: хранить данные репозитория один раз или копировать на каждого пользователя.

Дополнительно: импорт репозитория — это создание нового проекта. Нужна модель, отделяющая «репозиторий как технический объект» от «проект как нарратив разработчика».

## Решение

`github_repositories` — разделяемая таблица. Одна строка на `github_id` (числовой ID GitHub). Несколько пользователей могут ссылаться на одну строку через `project_repositories`.

`project_repositories` — связующая таблица: `project_id`, `github_repository_id`, `user_id`. Уникальное ограничение: `unique(user_id, github_repository_id)` — один пользователь не может привязать один репозиторий к двум своим проектам.

Импорт репозитория = создание `DRAFT + PRIVATE` проекта + запись в `project_repositories` в одной транзакции.

Привязка (link) = добавление записи в `project_repositories` для существующего проекта.

Отвязка (unlink) = удаление записи из `project_repositories`; данные `github_repositories` не удаляются.

Репозиторий без привязок не чистится автоматически в V1.

## Отвергнуто

- **Данные репозитория на пользователя** — дублирование данных; синхронизация усложнена.
- **Хранить full_name как ключ** — full_name может измениться при переименовании; `github_id` стабилен.

## Последствия

Данные репозитория синхронизируются один раз для всех привязок. `project_repositories.user_id` позволяет проверить ownership без JOIN через `projects`. Нужна логика orphan-cleanup для `github_repositories` без привязок (отложено после V1).
