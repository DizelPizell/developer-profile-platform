# ADR-0001: Серверная часть построена как модульный монолит

- **Статус:** принято 2026-10-01
- **Релиз:** v1

## Контекст

V1 содержит несколько логических доменов (Identity, Profile, Projects, GitHub, Analytics, Files), но не требует независимого развёртывания или масштабирования каждого из них. Microservices добавят операционную сложность без конкретной выгоды на текущем масштабе.

## Решение

Использовать модульный монолит: один деплойный юнит с явными границами между доменами в коде.

Логические контексты: Identity, Profile, Projects, GitHub, Analytics, Files.

Технологический стек: Python + FastAPI + SQLAlchemy 2 + PostgreSQL + Alembic; Next.js + TypeScript на фронтенде.

## Отвергнуто

- **Microservices** — нет конкретного требования, которое оправдывало бы операционную сложность.

## Последствия

- Проще локальная разработка, деплой и транзакции.
- Границы доменов защищаются конвенциями кода и ревью — автоматически не проверяются.
- Если потребуется выделить сервис, потребуется дополнительная работа.
