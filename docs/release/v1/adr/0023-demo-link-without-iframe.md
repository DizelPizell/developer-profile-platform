# ADR-0023: Демо в V1 — ссылка с превью, без встраивания в iframe

- **Статус:** принято 2026-11-17
- **Релиз:** v1
- **Связано:** [0022](0022-media-on-host-volume.md) — превью из первого скриншота; [0020](0020-contacts-separate-table.md) — правила URL контакта `OTHER`; [0021](0021-single-origin-behind-nginx.md) — один origin

## Контекст

PRD («Demo-first project page») требует: если у проекта есть живое демо, оно — первый крупный элемент страницы проекта; если встраивание запрещено (`X-Frame-Options`, CSP `frame-ancestors`), показать превью и действие «Open live demo».

Узнать, разрешено ли встраивание, браузер не даёт: заблокированный iframe не сообщает странице причину. Остаётся проверка с сервера — запрос бэкенда на произвольный URL пользователя, а это SSRF: нужны блокировка внутренних адресов, защита от DNS rebinding и перенаправлений на них. Кроме того, чужая страница внутри нашей выглядит как часть платформы — готовая площадка для фишинга под нашим доменом.

DATABASE_SCHEMA.md планировал для демо отдельную таблицу `project_demos` (0:1).

## Решение

1. **Без iframe.** Первый крупный элемент страницы проекта с демо — превью и основная кнопка «Открыть демо», ссылка в новой вкладке с `rel="noopener noreferrer"`. Превью — первый скриншот; без скриншотов — блок с адресом демо и той же кнопкой. Это запасной путь PRD, применённый ко всем проектам.
2. **Бэкенд не ходит по URL демо**: ни проверки доступности, ни заголовков, ни превью-снимков. Значит, нет SSRF.
3. **Хранение — столбец `projects.demo_url`** (nullable `TEXT`), а не таблица `project_demos`: у демо одно поле, отдельная сущность 0:1 ничего не даёт.
4. **Проверка URL — по правилам контакта `OTHER`** ([0020](0020-contacts-separate-table.md)): только `http` и `https` (схема в нижнем регистре), в хосте есть точка, без логина в URL, управляющих символов, пробелов и обратного слеша, до 2048 символов. `javascript:`, `data:` и другие схемы → `422 VALIDATION_ERROR`. Фронтенд повторяет проверку перед тем, как сделать ссылку.
5. **Демо не обязательно** для публикации проекта (PRD: «A project does not require GitHub or a demo»).

## Отвергнуто

- **iframe с проверкой заголовков на сервере** — SSRF-поверхность и фишинг в рамке ради того, что многие демо всё равно запрещают встраивание.
- **iframe без проверки** — у заблокированных демо пустая рамка, и браузер не даёт отличить её от медленной загрузки.
- **Снимок страницы демо на сервере** (headless-браузер) — тяжёлая инфраструктура и та же SSRF-поверхность.
- **Таблица `project_demos`** — см. п. 3.

## Последствия

- Страница проекта не зависит от того, разрешает ли демо встраивание; посетитель всегда видит одно и то же.
- Посетитель уходит с платформы, чтобы посмотреть демо; клики по демо — аналитика V1.1.
- Встраивание возвращается отдельным решением, если будет спрос, — с защитой от SSRF и списком разрешённых хостов.
