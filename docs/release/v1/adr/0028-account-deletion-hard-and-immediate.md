# ADR-0028: Аккаунт удаляется сразу и окончательно; просроченные сессии удаляются при входе

- **Статус:** принято 2026-11-20
- **Релиз:** v1
- **Связано:** [0022](0022-media-on-host-volume.md): файлы удаляются после коммита той же функцией, что у проекта; [0017](0017-repository-linking.md): репозиторий — общий ресурс; [0016](0016-github-public-only.md): токена пользователя нет; [0026](0026-backups-with-restic.md): снимки хранятся до 6 месяцев; [0020](0020-contacts-separate-table.md): персональные данные и юридические вопросы

## Контекст

До 9.7 разработчик может скрыть профиль и удалить проекты, но не может удалить аккаунт. Логин и email из GitHub, контакты и скриншоты остаются у нас навсегда. Просроченные строки `auth_sessions` тоже никто не удаляет: отложенный вопрос scope «Срок хранения сессий».

Каскады уже настроены: от `users` удаляются профиль, контакты, проекты, скриншоты, технологии проектов, витрина, привязки репозиториев, сессии и `github_accounts`.

## Решение

1. **`DELETE /api/v1/auth/me`** → `204` и очистка cookie. Удаление жёсткое и сразу: `DELETE FROM users`, остальное уходит каскадом базы. Миграции нет.
2. **Порядок**, как у удаления проекта:
   - блокировка профиля (`FOR UPDATE`), как в маршрутах проектов (ADR-015): параллельное изменение проекта ждёт, а потом не находит владельца;
   - ключи скриншотов всех проектов пользователя;
   - удаление строк и коммит;
   - удаление файлов через `storage.delete` (ADR-0022): ошибка пишется в лог, остаток убирает `app.media.sweep`.
3. **Общие `github_repositories` остаются.** В них только публичные данные GitHub, а строку могут использовать другие пользователи. Строку без привязок никто не синхронизирует: периодическая синхронизация идёт только для опубликованных проектов. Удаление вместе с аккаунтом дало бы гонку с воркером, который синхронизирует эту строку.
4. **Подтверждение** — диалог фронтенда (9.7b): ввести свой логин. В API подтверждения нет. От CSRF защищает Origin-проверка, от случайного клика — диалог.
5. **Доступ приложения в GitHub не отзывается**: токена пользователя у нас нет (ADR-0016). Экран удаления даёт ссылку на настройки приложений GitHub.
6. **Повторный вход** создаёт новый пустой аккаунт. Прежний slug освобождается, но строится из логина GitHub, поэтому, скорее всего, вернётся тот же.
7. **Восстановление из бэкапа** возвращает аккаунты, удалённые после снимка. Бэкенд пишет строку `account deleted user_id=<uuid>` с внутренним id, без логина и email, на уровне WARNING: процесс API ниже ничего не пишет. После восстановления владелец находит эти строки после даты снимка и удаляет аккаунты снова командой `python -m app.identity.delete_user <uuid>…` (DEPLOY.md). Таблица удалённых в базе не помогла бы: восстановление откатывает и её.
8. **Просроченные сессии** всех пользователей удаляются при каждом входе, одним `DELETE … WHERE expires_at <= now()` перед созданием новой сессии. Вход бывает чаще, чем раз в `SESSION_TTL_DAYS`, а строк — сотни.

## Отвергнуто

- **Мягкое удаление (`deleted_at`) с окончательным через N дней:** персональные данные хранятся дольше, чем нужно. Каждый запрос пришлось бы фильтровать, а для окончательного удаления нужна периодическая задача. Отмена удаления в V1 не нужна.
- **Подтверждение логином в теле запроса:** от CSRF защищает Origin-проверка. Украденную сессию поле не остановит: логин виден на публичной странице.
- **Повторный вход через GitHub перед удалением:** защищает от украденной сессии, но требует второго OAuth-потока с отдельным `state`. Для V1 избыточно.
- **Удаление `github_repositories` без привязок:** см. п. 3.
- **Таблица надгробий для восстановления:** см. п. 7.
- **Периодическая очистка сессий в воркере:** воркер — процесс синхронизации GitHub; очистки при входе достаточно.

## Последствия

- Удаление необратимо. Восстановить аккаунт можно только из бэкапа, целиком и только владельцу сервиса.
- Данные удалённого аккаунта остаются в снимках restic до 6 месяцев (ADR-0026). Это должна сказать политика данных (9.7b, проверка юриста в 9.8).
- Строки лога ротируются (5 файлов по 10 МБ): если восстанавливать старый снимок, часть строк `account deleted` может быть уже потеряна.
- Скриншот, загружаемый в момент удаления, может остаться файлом без строки. Его уберёт `app.media.sweep`.
- Просроченные сессии пользователей, которые больше не входят, удаляются, когда входит кто-то другой.
