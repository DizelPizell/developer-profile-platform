# ADR-0008: Kafka и Outbox не используются в V1

- **Статус:** принято 2026-10-03
- **Релиз:** v1
- **Связано:** [0002](0002-kafka-outbox-superseded.md) — заменено; [0009](0009-sync-worker-skip-locked.md) — конкретный механизм

## Контекст

[0002](0002-kafka-outbox-superseded.md) принял Kafka и Outbox для надёжной асинхронной синхронизации с GitHub. При пересмотре выяснилось, что операционная сложность (брокер, consumer groups, Outbox-relay, мониторинг) несоразмерна требованиям V1. PostgreSQL уже является надёжным источником истины и может хранить джобы напрямую.

## Решение

V1 не использует Kafka и не использует паттерн Outbox.

Синхронизация с GitHub остаётся асинхронной, но реализуется без брокера сообщений: таблица джобов в PostgreSQL + отдельный воркер-процесс ([0009](0009-sync-worker-skip-locked.md)).

Принятый жизненный цикл джоба: `NOT_SYNCED → QUEUED → SYNCING → SYNCED / FAILED → QUEUED` (ретрай).

Синхронизация должна быть идемпотентной.

## Отвергнуто

- **Kafka + Outbox** ([0002](0002-kafka-outbox-superseded.md)) — несоразмерно требованиям V1.
- **Синхронная синхронизация в HTTP-запросе** — может превышать разумное время, нельзя блокировать API.

## Последствия

Убирается Kafka и Outbox-relay. V1 деплоится только с PostgreSQL и процессами приложения. Гарантии надёжности, которые давала Kafka, реализуются через таблицу джобов (статус, счётчик попыток, timestamps, SKIP LOCKED).

Kafka может вернуться только при конкретном, наблюдаемом требовании, по новому ADR.
