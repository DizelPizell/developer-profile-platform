# ADR-0010: Модель данных GitHub Evidence: снэпшоты и история, правила согласования

- **Статус:** принято 2026-10-15; сужено [0018](0018-github-sync-v1.md) для V1
- **Релиз:** v1
- **Связано:** [0007](0007-github-evidence-source.md), [0011](0011-sync-partial-success.md), [0018](0018-github-sync-v1.md)

## Контекст

[0007](0007-github-evidence-source.md) установил, что GitHub — источник технических данных. Нужно определить: что именно синхронизируется, как классифицируются данные и как синхронизация остаётся идемпотентной при частичном сбое.

Примечание 2026-10-30: V1 синхронизирует только метаданные и языки ([0018](0018-github-sync-v1.md)). README, дерево файлов, контрибьюторы и коммиты отложены, не отклонены; правила ниже применяются к ним без изменений.

## Решение

### Объём (полный, реализация по ADR — поэтапно)

Метаданные репозитория, README, языки программирования, метаданные дерева файлов, контрибьюторы (данные GitHub как есть), коммиты (до 100 последних на запуск синхронизации).

Явно вне обязательного объёма V1: зависимости, pull requests, releases, CI/CD как отдельные сущности.

### Данные-снэпшоты — согласование

Метаданные, README, языки, дерево файлов, контрибьюторы — снэпшоты (текущее состояние GitHub).

Алгоритм согласования:
1. Загрузить полный снэпшот из GitHub (с пагинацией).
2. При сбое или неполном ответе — не удалять и не менять сохранённые данные.
3. Upsert всех присутствующих, удалить отсутствующих — в одной короткой транзакции PostgreSQL.
4. Запросы к GitHub — только вне транзакции.

### Данные-история — коммиты

Коммиты — история: только добавление, никогда не удаляются автоматически. `ON CONFLICT ... DO NOTHING` — уже сохранённый коммит не перезаписывается. Лимит 100 — на выборку за один запуск, не на суммарное хранимое количество.

Известное ограничение: если между двумя запусками появилось более 100 коммитов, они будут пропущены навсегда.

## Последствия

Один алгоритм согласования покрывает все категории снэпшотов. Снэпшоты и история имеют разные правила удаления, соответствующие их семантике. Транзакционная граница (fetch вне, write внутри) безопасна для физического удаления строк снэпшотов при частичном сбое.
