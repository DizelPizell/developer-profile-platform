# ADR-0019: Данные GitHub показываются на карточках проектов; агрегаты по профилю не вычисляются

- **Статус:** принято 2026-10-30
- **Релиз:** v1
- **Связано:** [0007](0007-github-evidence-source.md), [0014](0014-nextjs-ssr-public.md), [0018](0018-github-sync-v1.md)

## Контекст

V1 синхронизирует метаданные и языки репозиториев ([0018](0018-github-sync-v1.md)). Нужно определить: где и как показывать эти данные публично; нужно ли вычислять агрегаты по всем проектам профиля (суммарные языки, рейтинги активности).

## Решение

Данные GitHub показываются на карточках отдельных проектов — не агрегируются по профилю.

Публичный `github` объект в карточке проекта (`GET /api/v1/profiles/{slug}`) содержит ровно 10 полей: `full_name`, `html_url`, `description`, `stars`, `forks`, `open_issues`, `is_fork`, `is_archived`, `languages`, `synced_at`.

Объект `github` равен `null` если: нет привязки к репозиторию, синхронизация ещё не завершилась успешно для всех обязательных категорий, репозиторий недоступен (`unavailable_since` установлен), или привязка разорвана.

Данные GitHub никогда не запрашиваются из API во время HTTP-запроса — только из базы данных. Одним батчевым запросом для всех проектов профиля.

Агрегаты по профилю (суммарные языки, активность) — не вычисляются в V1. Это противоречило бы [0007](0007-github-evidence-source.md): нельзя создавать артефакты ранжирования из данных GitHub.

## Последствия

Нет дополнительных запросов к GitHub при загрузке публичной страницы. Нет агрегатов, которые могут вводить в заблуждение. `github = null` — корректное состояние, которое UI должен обрабатывать молча.
