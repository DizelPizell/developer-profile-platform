# ADR-0011: Синхронизация делит категории на обязательные и необязательные; частичный успех возможен

- **Статус:** принято 2026-10-15
- **Релиз:** v1
- **Связано:** [0009](0009-sync-worker-skip-locked.md), [0010](0010-github-evidence-model.md), [0018](0018-github-sync-v1.md)

## Контекст

Синхронизация GitHub состоит из нескольких HTTP-запросов к разным эндпоинтам (метаданные, языки, контрибьюторы, коммиты). Любой из них может упасть независимо. Нужно определить: считать ли джобу успешной только при полном успехе или допускать частичный результат.

## Решение

Каждая категория данных (`metadata`, `languages`, `contributors`, `commits`) отслеживается отдельно в `github_sync_category_status`.

Категории делятся на обязательные и необязательные:
- **Обязательные** (`metadata`): если хотя бы одна обязательная не SYNCED — джоба переходит в FAILED.
- **Необязательные** (`languages`, `contributors`, `commits`): могут быть FAILED без перевода всей джобы в FAILED; статус джобы определяется только обязательными.

Джоба переходит в `SYNCED`, если все обязательные категории имеют статус `SYNCED` и все остальные достигли терминального состояния (`SYNCED` или `FAILED`).

Статус каждой категории фиксируется в отдельной транзакции по мере завершения.

## Отвергнуто

- **Всё или ничего** — потеря успешно полученных данных при сбое в одной необязательной категории.
- **Единый флаг на джобу без категорий** — нет возможности ретраить только упавшую категорию.

## Последствия

Частичные результаты можно показывать в UI (с указанием свежести). Ретрай возможен для конкретной категории. Усложняется логика воркера — нужна сводная проверка всех категорий перед финальным переходом.
