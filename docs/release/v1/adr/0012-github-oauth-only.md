# ADR-0012: Единственный способ входа — GitHub OAuth; сессии хранятся на сервере

- **Статус:** принято 2026-10-01
- **Релиз:** v1
- **Связано:** [0016](0016-github-public-only.md) — доступ к GitHub API; [0003](0003-github-token-encryption.md) — хранение токена

## Контекст

Платформа построена вокруг GitHub как источника технических доказательств. Нужна аутентификация, минимально сложная для V1, но совместимая с дальнейшей интеграцией с GitHub.

Альтернативы: email+пароль, magic link, добавление GitHub OAuth как второго способа к основной аутентификации.

## Решение

GitHub OAuth — единственный способ входа в V1. Email+пароль не реализуется.

Сессии хранятся на сервере в таблице `auth_sessions`. В cookie хранится только идентификатор сессии. В `auth_sessions` хранится `token_hash` (SHA-256 от session token), не plaintext token.

Cookie: `HttpOnly`, `Secure` в продакшене, `SameSite=Lax`.

GitHub access token: в V1 используется только для получения email пользователя при первом входе; после этого доступ к GitHub API осуществляется через credentials приложения ([0016](0016-github-public-only.md)). Token не хранится в plaintext.

CSRF-защита реализована через Origin/Referer проверку на всех state-changing эндпоинтах ([0013](0013-profile-patch-origin-check.md)).

## Отвергнуто

- **Email+пароль** — дополнительная сложность, которую не требует V1.
- **JWT в localStorage** — уязвим к XSS; нет механизма инвалидации.
- **Несколько OAuth-провайдеров** — отложено после V1.

## Последствия

Вход требует GitHub-аккаунта. Серверные сессии позволяют немедленную инвалидацию при выходе. Нужна периодическая чистка просроченных сессий. `auth_sessions` — источник истины для текущих активных пользователей.
