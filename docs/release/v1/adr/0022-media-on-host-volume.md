# ADR-0022: Скриншоты хранятся в томе на диске хоста и отдаются Nginx; загрузка идёт через бэкенд

- **Статус:** принято 2026-11-17
- **Релиз:** v1
- **Связано:** [0021](0021-single-origin-behind-nginx.md) — один хост, один origin, направление для медиа (п. 8); [0015](0015-project-entities.md) — модель проекта; [0005](0005-project-lifecycle-visibility.md) — жизненный цикл и видимость; [0023](0023-demo-link-without-iframe.md) — превью демо из первого скриншота

## Контекст

Фаза 4 добавляет к проекту скриншоты: это первые файлы, которые загружает пользователь. CLAUDE.md и ARCHITECTURE.md закладывали «S3-compatible object storage, MinIO локально», `.env.example` — переменные `S3_*`, которые код не читает.

Что изменилось к моменту решения:

- MinIO Community Edition больше не поставляется: в октябре 2025 прекращены Docker-образы и бинарники, с декабря 2025 — режим поддержки, в 2026 репозиторий архивирован; против последнего релиза есть открытые CVE. Ставить его в продакшн нельзя.
- Продакшн V1 — один хост с Docker Compose, медиа отдаются с того же origin ([0021](0021-single-origin-behind-nginx.md)).
- Объём V1 маленький: до 6 скриншотов на проект, около 1 МБ каждый после перекодирования.

Варианты: том на диске хоста; своё S3-совместимое хранилище (Garage, SeaweedFS, RustFS, форк MinIO); облачный S3 у провайдера.

## Решение

1. **Хранилище — именованный том `media` на хосте.** Бэкенд пишет в него (`MEDIA_ROOT`, в контейнере `/srv/media`), Nginx монтирует его только для чтения и отдаёт по `location /media/`. Отдельного сервиса нет. Весь код записи и удаления — в одном модуле (`app/media/`): переход на S3 заменит только его.
2. **Загрузка — через бэкенд**, `multipart/form-data`, а не presigned URL: проверка файла и перекодирование нужны до того, как файл станет публичным.
   - Принимаются JPEG, PNG, WebP до 5 МБ; формат определяется по содержимому, не по расширению и не по `Content-Type`.
   - Файл открывается Pillow с ограничением на число пикселей (защита от «бомб» декомпрессии) и перекодируется в WebP с длинной стороной до 2560 px. Перекодирование убирает EXIF, в том числе GPS, и подтверждает, что это изображение.
   - Pillow — новая зависимость, потому что ничем установленным картинку не проверить и не перекодировать; версия закреплена в `requirements.lock`.
   - Nginx поднимает `client_max_body_size` до 6 МБ только на пути загрузки скриншотов; на остальном API остаётся 1 МБ.
3. **Имена файлов** — `projects/{project_id}/{uuid}.webp`, новый UUID на каждую загрузку. Имя не угадать, а содержимое по имени не меняется, поэтому Nginx отдаёт `/media/` с `Cache-Control: public, max-age=31536000, immutable`.
4. **Модель** — таблица `project_screenshots`: `project_id` (каскад при удалении проекта), `position`, `caption` (до 200 символов, она же `alt`), `storage_key`, `width`, `height`. Не больше 6 на проект — инвариант бэкенда, как 3 избранных проекта.
5. **Видимость.** URL скриншота черновика или закрытого проекта доступен тому, кто его знает: имя не угадать, а при удалении проекта или скриншота файл удаляется. Скрытие проекта или профиля URL не отзывает. Проверять доступ к каждой картинке через бэкенд дороже (каждый запрос картинки — в Python и базу), а выгода мала: пользователь сам решает, что загружать. Публичные ответы отдают скриншоты только видимых проектов.
6. **Очистка.**
   - Удаление проекта или скриншота: строка удаляется в транзакции, файлы — после коммита; ошибка удаления файла пишется в лог и не откатывает операцию.
   - Загрузка: файл пишется до вставки строки; если транзакция не прошла, файл удаляется в обработчике ошибки.
   - Остатки после падения процесса между этими шагами убирает ручная команда `python -m app.media.sweep`: файлы без строки в базе старше суток. Периодический запуск — если команда понадобится чаще, чем раз в месяц.
   - Удаление аккаунта (9.7) использует ту же функцию удаления файлов проекта.
7. **Разработка.** Без Nginx файлы отдаёт сам FastAPI (`StaticFiles` на `/media`), только при `APP_ENV=development`. Адрес картинки в ответах API — путь `/media/...` относительно origin сайта.

_Правка 2026-11-18 (шаг 4.2a): вторая новая зависимость — `python-multipart`: без неё FastAPI не читает `multipart/form-data` (п. 2). Альтернатива — «сырое» тело `image/*` с подписью отдельным запросом — делала загрузку двухшаговой. Подпись необязательна (`caption` nullable), `alt` без подписи строит фронтенд. Порядок меняется `POST /projects/{id}/screenshots/reorder`, как у витрины, — не `PUT`._

## Отвергнуто

- **MinIO** — не поставляется и не получает исправлений (см. «Контекст»).
- **Своё S3-совместимое хранилище** (Garage, SeaweedFS, RustFS, форк MinIO) — ещё один сервис с неясной зрелостью и поддержкой, а файлы лежат на том же диске: надёжнее тома не становится.
- **Облачный S3** — внешняя зависимость, ключи и оплата ради 6 МБ на проект; картинки либо со второго origin, либо через прокси Nginx.
- **Presigned PUT напрямую в хранилище** — файл становится доступным до проверки; проверять и перекодировать пришлось бы задним числом.
- **Проверка доступа к каждой картинке через бэкенд** — см. п. 5.

## Последствия

- Новых сервисов нет; том `media` добавляется в бэкапы (9.5) и в мониторинг свободного места (9.6).
- Хранилище привязано к хосту — как и вся топология V1. Переход на облачный S3 пересматривает решение, если появится второй хост, перестанет хватать диска или понадобится CDN.
- Перекодирование нагружает процессор единственного процесса uvicorn; синхронный обработчик FastAPI выполняется в пуле потоков, поэтому остальные запросы не встают. При 6 файлах на проект это приемлемо.
- `S3_*` убираются из `.env.example`; упоминания MinIO и S3 — из CLAUDE.md и архитектурных документов.

## Риски

- Pillow разбирает недоверенные файлы, и в нём бывают CVE. Ограничиваем размер, число пикселей и форматы, закрепляем версию и обновляем её (8.4). Проверяем в 4.2 тестами на файл с поддельным расширением, на «бомбу» декомпрессии и на EXIF с GPS.
