# C4 Model

## Level 1 - System Context

### People
- Developer — has an account; creates and manages their profile and projects.
- Recruiter / Employer — anonymous reader of public profiles in V1; no account, no V1-specific roles or flows. Recruiter accounts, candidate search and vacancies are V2.
- Technical Reviewer — anonymous reader of public profiles and project workspaces in V1.

### System
Developer Professional Profile Platform

### External systems
- GitHub
- S3-compatible Object Storage

## Level 2 - Containers

### Web Application
Next.js + TypeScript. Public profiles, dashboard, project pages, technical workspace and analytics UI.

### Backend API
FastAPI + Python. Authentication, business rules, profiles, projects, GitHub, analytics and files.

### PostgreSQL
Users, profiles, projects, normalized GitHub data, analytics and application state.

### Object Storage
Avatars, screenshots and other uploads.

### GitHub Sync Worker
Separate process. Polls `github_sync_jobs` in PostgreSQL and claims work with `SELECT ... FOR UPDATE SKIP LOCKED` — no broker, no Outbox relay. See ADR-009-github-sync-worker-execution-model.md.

## Level 3 - Backend Components

```text
FastAPI
 |
 +-- Auth
 +-- Profile
 +-- Projects
 +-- GitHub
 +-- Analytics
 +-- Files
 +-- Users
 |
 +-- API Layer
 +-- Application Layer
 +-- Domain Layer
 +-- Persistence Layer
 +-- Infrastructure Layer
```

Exact package layout can evolve, but domain boundaries must remain clear.
